## 推荐职责分离

先用一个进程跑通 MVP，不以前置价值对照为条件。HTTP API 作为程序入口，MCP 满足云端/本地 Agent 接入，两者共享核心和 SQLite；以私有插件分发 MCP 与轻量 Skill。密钥在服务端保管，复用现有 VPS 和 HTTPS 入口，新增独立服务路由。

- 云端 VPS：独立服务用户、release/current、持久数据目录及 systemd 单元；判断计算由 OpenAI 承担，不需要本服务 GPU。复杂缓存和高可用按使用需要增加。
- 既有协调与执行端：保留任务派发、原检查点接续和业务执行职责；Mac 的 Herdr 消费者按固定提交独立安装，已核真实工程单元的采用、配置读回及结果回传。既有在途 runner 和生产角色未切换。
- 既有 Hindsight：复用已有记忆服务，不复制第二套记忆库。
- 具体部署实例、域名、私网路由和密钥在私有运维配置中管理，不写入公开仓库。

“公共服务”指多个授权项目共享，并非匿名开放。公开源代码不意味着公开运行中的服务或业务数据。

## MVP 联调与运行准备

- 所选运行位置能够启动服务，消费者能够访问所需入口；
- 实际账户可调用 Decisions，调用预算和超时可配置；
- Hindsight 可读取首批配置的相关 bank，来源和部分失败能返回；
- 原 workflow 与角色创建者能消费所选动作/模型配置，宿主不支持的操作明确返回；
- 调用记录、适配器直传的 application/result 与人工纠正可保存、查询，并沿原任务/工作单元及可得执行引用关联，不强求不存在的原生字段；
- 原检查点能持久保留待回传事件，恢复或后续检查点补传原事件；同事件/同 revision 重复接收幂等，质量更新使用新 revision，反馈故障不重跑业务。

小规模 MVP 使用单实例、SQLite 持久记录与原端恢复补传，不先建设完整审计、全库补偿与性能评测平台。已具备的真实账户、入口和宿主工程证据逐项记录；自然任务采用、质量与效率另行观察，不因进程健康或一次样例承诺高并发、HA、端到端毫秒延迟或固定加速倍数。

消耗计量优先级低：只附带现有响应/回执中直接可得的 token、耗时等，缺省留省略/null，不补零、不新增采集或账单链路，现金费用不记录。模型类型/型号与推理强度需要记录，推荐与实际配置分开，实际不可读标未确认；缺消耗数据不影响 MVP 跑通。

## SQLite 运行边界

- 数据库位于服务主机的持久数据目录，与临时目录、代码发布目录分开；若使用容器，该目录挂载持久卷。重启和更新应保留原决策与反馈记录，首版联调核对重启后可读回，不要求搭建高可用平台。
- 多个项目和 Agent 经 HTTP/MCP 访问同一服务，不把数据库文件放到跨主机共享目录供消费者直接打开，也不向消费者分发 SQLite 副本进行写回。
- 服务短事务保存记录；模型/检索等网络等待在事务外。反馈写入成功才确认收回，同事件重投沿原幂等合同处理。
- SQLite 保存决策、已收反馈及关联，原端检查点仍保存待传事件；服务库无法替代原端未回传数据的恢复。记录种类和归属以[架构设计](architecture.md#内部存储与数据归属)为准。

服务使用 Python 标准 sqlite3，持久目录由 systemd StateDirectory 管理；配置和分开的上游/OAuth 凭据使用 LoadCredential。OAuth 登记和令牌状态在独立加密目录保存，限制 8 MiB、512 文件，超限拒绝新写且保留旧记录。单机 SQLite 不提供跨主机共享写入或自动高可用；实际出现多实例写入需求时再评估存储迁移。

## 应用与结果回传

适配器自动直传实际应用动作/模型配置或未采用原因，并在原工作单元/执行 attempt 有结果时直传其引用及已有质量、usage；人工纠正保留。decision_id 随原任务标识保存，角色跨任务按任务单元回收，不等待角色退出。服务端先持久保存再确认接收；原端沿检查点保存待回传事件，恢复或后续检查点补传，不因回传失败阻塞后续业务或重跑业务，不新建总线或独立业务状态机。

结果采用已有测试与原验收信息，不逐单增加人工评价。多项决策关联同一执行 attempt 时，执行成本只计一次，服务判断 attempt 另计；并发墙钟时间不能相加。应用回收率与已知结束单元的结果回收率分开，在途、未知与缺口另列；缺 token 或结果保持 UNKNOWN，关联不等于因果。字段、事件修订、恢复与统计口径统一见[结果回收与效果验证](outcome-feedback.md)，本页不另定义一套合同。

MVP 直传的反馈保存在 Decision Service，可独立运行。凡人 bank 已另行启用 P3 原生 webhook，验证了一条真实历史结果的回收、按文档 ID 补偿与重启读回。生产者由受控命令触发，全库遗漏扫描尚未接入。[生产回收证据](evidence-and-open-questions.md#凡人单-bank-生产回收2026-11-09)

## 隔离与权限

- 复用现有认证与入口设施，服务调用记录不混入其他服务的业务数据库；不要求首版建立动态权限或资源调度平台。
- API key 保存在服务端安全配置中，不进仓库、Skill、项目上下文或日志。
- 用静态配置限定入口/调用者可读 bank 与预算，同权限调用者可共用；问题与候选允许直接提交，不逐场景审批。project_id 或 caller_role 自报值不能扩大读取范围。
- 多 bank 只读直接入首版，不要求逐次批准或先复制共享经验；读取不自动取得 retain、删除或管理权限。MVP 的 application/result 与人工纠正保存在服务记录中，不依赖 Hindsight 混合读写权限扩展。
- 使用最小模型与接口权限；账户/key 权限仍需实施时实际验证。
- 凡人 P3 试点已为凡人 bank 启用回调、配置独立生产者和调用作用域，并向现有服务只读主体加入该 bank。实际凭据与入口配置保存在受控落点。部署前已备份配置与 SQLite，并保留原发布供回退。
- 不提供任意命令执行、shell、业务派发或用户审批写入口。

## 故障处理

| 故障 | 预期行为 |
| --- | --- |
| Decisions 超时/拒绝/返回异常 | 无有效建议时 unavailable / abstain / needs_review，回原路径；超时是否已推理另记处理状态 |
| Hindsight 或部分 bank 不可用 | 用已有上下文继续并注明缺口；关键证据缺失才回退，不凭空补历史 |
| 决策服务故障 | 回到原流程，不让建议服务成为全系统唯一可用路径 |
| 业务执行端离线 | 不声称已派发、执行或接续，沿原执行者恢复 |
| MVP 应用/结果直传失败或响应丢失 | 原检查点保留待回传事件，恢复或后续检查点补传原事件；服务端按事件/revision 幂等接收，缺口可见，不阻塞后续业务、不重跑业务 |
| 后续 Hindsight 写回失败 | 未知/处理中先查原 operation；确认失败后沿原失败处置，显式新尝试与旧操作关联，业务结果不回滚 |
| 输入版本过期 | 接入 workflow 时原执行器采用前复核所依赖状态，失配时按当前状态重新判断；普通问答不虚设任务版本 |
| 模型响应丢失 | 能定位时查已有记录；允许预算内留痕重算纯判断，不能冒充原答案恢复，不承诺恰好一次收费 |
| 模型配置或计划调整无法应用 | 由原创建者/执行器说明不支持的组合或变更，修正候选；不把推荐返回当成已切换/已推进 |
| 业务执行结果未知 | 原 ID 对账，不因模型建议重试而重新执行 |

本项目不承担既有执行器、消息收集器或审批通知系统的修复；这些是独立依赖，不得隐藏在决策服务上线声明中。
