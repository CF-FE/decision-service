# ADR-001：独立公共决策服务与薄接入层

- 日期：2026-11-08
- 状态：方向已采纳（用户确认先跑通跨 bank MVP，并明确效率/模型选型目标）；接口及实现细节仍为草案，未开发、未运行验收
- 范围：跨项目快速模型判断，不是用户审批系统

后续补充：[ADR-002](002-mvp-deliverables-and-sqlite.md)已确定 HTTP 首版程序入口、按需求提供 MCP、轻量 Skill 与 SQLite 存储；本记录原先“HTTP 或 MCP 先择一”和“存储待决”的范围按该补充收敛，其余共享核心与责任边界继续有效。下文保留此前方向及取舍。

## 背景

Router 协调员、项目负责人和工作流需要共享快速分类、评分与候选分支判断，并利用 Hindsight 历史经验。仅靠各 Agent 的提示词会分散密钥、规则版本、审计和成本控制。

用户进一步明确：提高动态工作流执行效率和模型 token 利用率；快速判断如何调整/推进工作流，在创建角色时按任务需求与复杂度选择模型类型及推理强度。[讨论与确认范围](../discussion-record.md#用户确认的最新方向与补充)

## 已采纳方向

保留独立 decision-service 仓库与共享核心，先做一个可运行 MVP，提供通用 evaluate、跨 bank 检索，以及 workflow_next_action / role_model_selection 预设。一个进程先接实际需要的 HTTP 或 MCP 入口；不以前置收益证明、完整评测或逐场景 profile 审批阻塞建设。

静态配置可读 bank 范围，同权限受信调用者可共用配置；允许直接检索其他项目 bank，不要求先复制为共享经验或逐次批准。问题/候选可由调用方直接提交，常用内容存预设；选择动作由原 workflow 应用，模型配置由原角色创建入口应用，服务不接管计划状态或角色生命周期。

创建角色时先匹配工具/模态/上下文等能力，再按复杂度和预算选择预计足够的模型/强度；工作流在实质决定点调用，不在每个节点重复判断。实际使用后的总 token、耗时、返工和纠正帮助改善策略。基线、消融和正式评测保留为迭代工具，完整 webhook 自动回收后置。

用户已确认将最小结果回收与效果验证补入 MVP：原适配器自动回传 application/result，按原任务与执行单元关联实际采用、结果、质量及消耗；原检查点持久保留待传事件，恢复补传不重跑业务。服务负责事件幂等/质量修订、关联查询、覆盖缺口与效果汇总，人工纠正作为补充。回收事实不自动证明决策最优；详细合同归[结果回收方案](../outcome-feedback.md)，Hindsight webhook/全库补偿仍后置。

用户进一步明确：消耗计量优先级低，仅记录现成可直接取得的值，取不到留缺省，不做现金费用记录；模型类型/具体型号和推理强度必须留记录。由此撤掉首版专门接通用量采集的要求，应用、质量与结果反馈仍保留；配置的推荐/实际值和未确认情况分别记录。

本条是对同一未实施提案的方向修订。用户已确认上述方向并要求先修订文档、先不开发；不将方向采纳写成部署、运行验收或凭据配置授权。[路线图](../roadmap.md)描述后续建设顺序。

## 替代方案

- 仅 Skill：不足以提供统一认证、模型调用和稳定程序合同。
- 仅 MCP：可服务 Agent，但工作流直接 API 调用更简单。
- 直接并入 Herdr：短期适配更少，但与跨项目公共能力目标耦合。
- 新审批平台：不采用，避免与既有用户授权、审批状态和执行检查点重叠。
- 先做价值对照再建设：首轮评审曾推荐；用户认为过于保守，现改为先跑通 MVP。对照方法留作后续优化。
- 各项目嵌入 SDK：少一个网络跳转，但可能分散密钥、版本与运维；不作为默认推广方式。
- 同时建设完整双入口、动态权限与自动反馈平台：首版只需一个实际入口和简单配置，后续按使用需要补齐。

## 后果与边界

- 新增独立服务的认证、版本、可观测与维护成本。
- 服务只提供模型建议及其证据，不产生用户批准或业务验收。
- 不更改 Herdr 已有审批 ADR，不将 OpenAI Decisions 与 Herdr approval decision 混用。
- 跨 bank recall 是首版能力，单次调用按上下文需要使用；读取不自动授予写入/删除权限，历史不替代当前任务状态。
- 原授权内的正常推进可直接消费结果，影子观察按具体场景选用，不作为统一必经阶段。
- 候选方案生成、计划应用及模型实际切换沿原系统能力；有限答案选择不等于任意计划生成或已完成角色切换。
- 允许低成本迭代与预算内重算，接受首版效果未知；记录真实使用中的纠正与可得计量，不冒充已有质量/效率证明。
- 统一判断记录不代表统一业务状态；原系统保有项目映射、授权、采用前状态检查、派发及验收责任。
- 任何部署、凭据与持久访问配置另在实施阶段核验授权。

## 待决

首个接入 workflow/角色创建入口、真实动作与模型候选、语言/框架、运行位置、具体可读 bank 与身份配置、调用预算和初始策略。存储引擎已由 ADR-002 确定为 SQLite，具体驱动/表结构待实现。按联调需要选择，不等待完整收益数据；当前没有实际访问或配置这些资源。业务负责人/验收者按实际任职绑定确认，不能从本次评审者推定。
