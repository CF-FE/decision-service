# ADR-002：首版对外交付物与 SQLite 存储

- 日期：2026-11-08
- 状态：已采纳（用户明确确认首版用 SQLite，并要求补入文档）；尚未开发、部署或运行验收
- 范围：首版服务交付形式、持久记录与既有系统的数据归属
- 关联：[ADR-001](001-shared-decision-service.md)的共享核心与责任边界继续有效；本记录将首版“HTTP 或 MCP 先择一”和“存储待决”收敛为以下选择

## 背景与确认依据

跨项目工作流需要稳定程序入口，Agent 需要工具入口，角色需要简洁的使用规范；两端同时需要精确查询决策及反馈。当前方案为单实例、小规模 MVP，优先跑通实际选择、应用与结果回收。

用户在了解 API/MCP/Skill 与 SQLite 方案后明确确认首版选型，并要求同步关联会话互审、先不开发。[原话与确认范围](../discussion-record.md#首版交付物与-sqlite-选型确认)

## 已采纳决定

1. 一个 Decision Service 核心，以 **HTTP API** 作为首版程序入口；按 Agent 实际接入需求提供 **MCP**。两者共用判断逻辑、认证作用域、请求/反馈标识和记录，不要求拆成两个进程。
2. 首版提供轻量 **Skill**，说明调用时机、事实与候选准备、结果应用/回退及反馈。插件只负责后续安装分发，不是首版前置。Herdr/项目适配器属于关联仓库的首版配套交付。
3. 首版使用 **SQLite**，数据库放在服务主机持久数据目录，由服务访问。保存决策记录、反馈事件及修订、与原工作单元的关联和回收信息；具体驱动、表结构与路由随实现确定。
4. 服务自身的判断模型与推荐/实际执行模型分别记录类型、型号和推理强度。消耗仅附带直接可得值，缺失留缺省；现金费用及等价估价不记录。
5. Hindsight 继续承担经验检索；原系统保有业务状态、产物/验收权威和待传事件。SQLite 保存服务收到的反馈，原端负责未回传记录的恢复补传。

详细交付及数据设计归[架构](../architecture.md#对外交付物)，事件修订与接收语义归[反馈合同](../outcome-feedback.md#最小反馈合同)，数据目录归[部署设计](../deployment.md#sqlite-运行边界)。

## 选择理由与替代方案

- SQLite 可在服务进程内保存确定性关联与事务记录，避免首版另运维数据库服务。[官方适用场景](https://www.sqlite.org/whentouse.html)包含由应用服务器封装访问的服务端数据库；这是选型依据，不是本项目容量验证。
- PostgreSQL 等独立数据库暂不引入：当前没有多实例共享写入需求。以后确有持续写入争用或多实例需求再评估，不先建设兼容层。
- 仅文件日志或仅 Hindsight 不作为本次记录方案：前者仍需自行处理关联、修订和查询，后者的语义检索不承担精确结果回收和去重。

## 后果与边界

SQLite 记录需要随服务重启/更新保留；反馈相关写入在短事务内完成，提交后才确认，模型和检索等待放在事务外。数据库由服务单实例管理，多个消费者通过 API/MCP 调用，不直接共享远程数据库文件。单机存储不提供自动高可用，当前不承诺容量或延迟指标。

本记录确认设计，不创建数据库、安装驱动、生成接口代码或变更运行权限。文档互审与后续实现/运行验收分别记录。
