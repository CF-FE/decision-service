# 路线图与验收

当前仅完成项目初始化、讨论文档和看板，不代表下述开发已开始。所有阶段无承诺日期、无默认负责人。

## P0：收敛场景与证据

选定 3–5 个高频有限答案场景；为每个场景定义角色、输入、候选选项、unknown/review 和错误成本。准备去敏历史标注集，划分开发与保留评估集。

验收：每个场景有明确非目标、预期结果、人工标签及来源；不存在用模型代替用户批准或业务验收的任务。

## P1：明确合同与最小服务

定义请求/响应、身份与项目隔离、配置版本、错误语义、审计、缓存失效、模型适配；先实现无业务副作用的 evaluate/get。HTTP 与 MCP 共用核心，Skill 记录角色使用规范。

验收：正常、拒绝、无效枚举、超时、过期状态、跨项目访问、重复 ID 和冲突输入测试覆盖；凭据不入日志；模型实际 API 合同核验通过。

## P2：接入 Hindsight

实现最小 recall 与来源引用；不默认 reflect。已验证反馈异步 retain 作为独立功能，保持稳定文档和操作 ID。

验收：项目 bank 隔离、来源/日期保留、冲突记忆、离线降级、异步完成和补写语义测试通过；建议不会被误写为事实。

## P3：离线回放与影子模式

先回放标注集，再旁路接入真实流程，只记录建议与人工选择，不改变业务。

指标：各类别准确率/召回率、错误成本、abstain 比例、人工纠正率、P50/P95 延迟、每次判断成本、模型和检索失败率。阈值按场景校准，不凭统一高分自动放行。

验收：保留评估集报告、真实分布差异、失败样例、回退率与预算齐全；没有未授权副作用。

## P4：低风险灰度与部署

在容量、网络、身份和凭据审批完成后，选择一个可逆低风险分流场景。先限项目与流量，保留负责人路径，支持一键退回影子模式。

验收：灰度范围明确、版本可追溯、回退演练完成、未知状态不会重复执行、监控与成本预算可用。最后才考虑推广到其他项目。

## 本次不做

不创建 API key、不安装服务、不部署 VPS、不修复现有 collector、不建立第二套审批系统、不自动写入 Hindsight 新经验、不启动真实业务派发。
